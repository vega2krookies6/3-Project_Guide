# API 설계서

> `{ }` 로 표시된 부분은 팀의 업무(주제)에 맞게 작성합니다.
> **3장 인증 API**는 업무와 무관하게 모든 팀이 구현하는 공통 API입니다.

## 1. 기본 정보

| 항목 | 내용 |
|------|------|
| Base URL | `http://{host}:8080/api` |
| 인증 방식 | JWT – `Authorization: Bearer {accessToken}` |
| Access Token 만료 | |
| Refresh Token 만료 / 전달 방식 | |
| Content-Type | `application/json` (파일 업로드는 `multipart/form-data`) |

## 2. 공통 규격

### 2.1 성공 응답
```json
{
  "success": true,
  "data": {},
  "message": ""
}
```

### 2.2 오류 응답
```json
{
  "success": false,
  "error": {
    "code": "",
    "message": ""
  }
}
```
> 오류 응답에 스택 트레이스·SQL·내부 경로를 포함하지 않습니다.

### 2.3 페이징 (목록 조회 공통)
| 파라미터 | 설명 | 예 |
|----------|------|----|
| page | 페이지 번호 (0부터) | `?page=0` |
| size | 페이지 크기 | `&size=10` |
| sort | 정렬 | `&sort=createdAt,desc` |

### 2.4 HTTP 상태 코드
| 코드 | 설명 |
|------|------|
| 200 | 성공 |
| 201 | 생성 성공 |
| 400 | 잘못된 요청 (입력값 검증 실패) |
| 401 | 인증 실패 (토큰 없음·만료·위변조) |
| 403 | 권한 없음 (역할 부족, 다른 사용자의 리소스) |
| 404 | 리소스 없음 |
| 409 | 중복 (이미 가입된 이메일 등) |
| 423 | 계정 잠금 (로그인 실패 횟수 초과) |
| 429 | 요청 과다 (적용한 경우) |
| 500 | 서버 오류 (상세 내용은 서버 로그에만 기록) |

## 3. API 목록 요약

| 구분 | 메서드 | URL | 설명 | 인증 | 권한 / 소유자 검증 |
|------|--------|-----|------|------|--------------------|
| 인증 | POST | `/auth/signup` | 회원가입 | X | - |
| 인증 | POST | `/auth/login` | 로그인 | X | - |
| 인증 | POST | `/auth/refresh` | 토큰 재발급 | X (Refresh Token) | - |
| 인증 | POST | `/auth/logout` | 로그아웃 | O | 본인 |
| 사용자 | GET | `/users/me` | 내 정보 조회 | O | 본인 |
| 업무 | {메서드} | `/{리소스}` | {설명} | | |
| AI | POST | `/ai/{기능}` | {AI 기능} | O | 본인 데이터만 |

## 4. 인증 API (공통)

### 4.1 회원가입
- **POST** `/auth/signup`
- Request
```json
{ "email": "", "password": "", "name": "" }
```
- Response `201`
```json
{ "success": true, "data": { "uuid": "" }, "message": "" }
```
- 오류: `400` 입력값 검증 실패, `409` 이메일 중복

### 4.2 로그인
- **POST** `/auth/login`
- Request
```json
{ "email": "", "password": "" }
```
- Response `200`
```json
{ "success": true, "data": { "accessToken": "", "refreshToken": "" }, "message": "" }
```
- 오류: `401` 인증 실패, `423` 계정 잠금
- 보안: 실패 시 "이메일 또는 비밀번호가 올바르지 않습니다"로 통일 (계정 존재 여부 노출 금지)

### 4.3 토큰 재발급
- **POST** `/auth/refresh`
- Request
```json
{ "refreshToken": "" }
```
- Response `200` – 새 Access Token / Refresh Token (기존 Refresh Token은 폐기)
- 오류: `401` 만료·폐기된 토큰

### 4.4 로그아웃
- **POST** `/auth/logout`
- 처리: 서버에 저장된 Refresh Token 폐기

## 6. AI API (Frontend → Backend)

> Frontend는 AI Module을 직접 호출하지 않고, 반드시 Backend API를 통해 호출합니다.

### 6.1 {AI 기능명} (예: 질의응답)
| 항목 | 내용 |
|------|------|
| 메서드 / URL | POST `/ai/{기능}` |
| 인증 | O |
| 응답 방식 | 일반(JSON) / 스트리밍(`text/event-stream`, SSE) |
| 입력 제한 | 예: 질문 최대 길이 |

- Request
```json
{ "question": "" }
```
- Response (스트리밍 시 이벤트 형식)
```
data: {"token": ""}
data: [DONE]
```

### 6.2 {AI 관련 파일 업로드} (RAG 사용 시)
| 항목 | 내용 |
|------|------|
| 메서드 / URL | POST `/ai/{리소스}` |
| Content-Type | `multipart/form-data` |
| 허용 형식 / 최대 크기 | 예: PDF, TXT / 10MB |

## 7. 내부 API (Backend → AI Module)

> AI Module(FastAPI)의 API는 **외부에 공개하지 않습니다.** Backend만 호출합니다.

| 메서드 | URL | 설명 | 요청 | 응답 |
|--------|-----|------|------|------|
| POST | `http://{ai-service}:8000/{경로}` | | | |
| GET | `http://{ai-service}:8000/health` | 헬스체크 | - | `{"status":"ok"}` |
