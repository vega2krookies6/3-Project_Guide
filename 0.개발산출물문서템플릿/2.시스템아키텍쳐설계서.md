## 6. 보안 아키텍처

> 상세 점검 결과는 `9. 보안점검서.md` 에 작성합니다. 여기서는 **구조적 보안 설계**만 기술합니다.

### 6.1 신뢰 경계(Trust Boundary)
- 외부 공개 구간 / 내부 전용 구간 구분 (예: AI Module, DB는 외부 비공개)
- 각 구간 사이의 인증·인가 방식

### 6.2 인증·인가
- 인증 방식: JWT (Access Token 만료시간 / Refresh Token 저장·폐기 방식)
- 인가 방식: 역할(Role) 기반 + 리소스 소유자 검증
- Backend ↔ AI Module 간 내부 인증 방식

### 6.3 보안 설계 원칙 적용 내역
> 아래는 **작성 예시**입니다. 우리 팀이 실제로 적용한 내용으로 수정하세요.

| 원칙 | 우리 시스템에서의 적용 |
|------|------------------------|
| Defense in Depth (다중 방어) | 보안그룹(80만 개방) → JWT 필터 → `@PreAuthorize` → 서비스 계층 소유자 검증 → JPA 파라미터 바인딩 |
| Least Privilege (최소 권한) | 앱 전용 DB 계정 사용, Actuator `health,info`만 노출(ADMIN 전용), AI Module은 Backend만 호출 가능 |
| Secure by Default | `anyRequest().authenticated()` 기본 거부, CORS Origin 한정, `ddl-auto: validate` |
| Never Trust Input (입력값 불신) | DTO `@Valid` 검증, 경로 ID 소유자 확인, JWT 서명·만료 검증, LLM 입력 길이 제한 |

### 6.4 비밀정보 관리
- 관리 대상: DB 비밀번호, JWT secret, LLM API Key 등
- 관리 방식: 환경변수 / GitHub Secrets / K8s Secret (코드 내 하드코딩 금지)
