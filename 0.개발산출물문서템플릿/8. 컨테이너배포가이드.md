# 컨테이너화 및 배포 가이드

## 1. 컨테이너 구성

- **Frontend**: React + Nginx
- **Backend**: Spring Boot
- **AI Module**: Python 3.12 + FastAPI
- **Database**: MariaDB

## 2. Docker 설정

### 2.1 Frontend Dockerfile
```dockerfile
FROM node:22-alpine AS build
# 빌드 과정
FROM nginx:alpine
# 배포 설정 (정적 파일 서빙, SPA 라우팅 fallback)
```

### 2.2 Backend Dockerfile
```dockerfile
FROM eclipse-temurin:17-jre
# 멀티스테이지(Maven 빌드 → JRE 실행), HEALTHCHECK
```

### 2.3 AI Module Dockerfile
```dockerfile
FROM python:3.12-slim
# uv 바이너리 복사 (수업 사용 버전으로 고정)
COPY --from=ghcr.io/astral-sh/uv:0.12.23 /uv /uvx /bin/
WORKDIR /app
# 의존성 먼저 설치 (레이어 캐시 활용), uv.lock 과 일치하지 않으면 빌드 실패
COPY pyproject.toml uv.lock ./
RUN uv sync --locked --no-dev
COPY . .
# uvicorn 으로 FastAPI 실행
CMD ["uv", "run", "uvicorn", "src.api.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

> `.dockerignore` 에 `.venv`, `.env`, 개발용 Vector DB 파일을 등록해 이미지에 포함되지 않게 합니다.

## 3. Docker Compose

```yaml
services:
  database:
    image: mariadb:10.11
    env_file: .env          # .env 는 Git 에 커밋하지 않는다
    volumes:
      - db-data:/var/lib/mysql
    # ports 미지정: 외부 비공개

  ai-service:
    build: ./ai-module
    # ports 미지정: Backend 에서만 접근

  backend:
    build: ./backend
    depends_on:
      - database
      - ai-service

  frontend:
    build: ./frontend
    ports:
      - "80:80"
    depends_on:
      - backend

volumes:
  db-data:
```

> 외부에 공개하는 포트는 최소화합니다. (DB, AI Module 포트는 호스트에 게시하지 않는 것을 권장)

## 4. 환경 변수

### 4.1 개발 환경
```env
DB_HOST=localhost
DB_USER=dev_user
AI_SERVICE_URL=http://ai-service:8000
LLM_PROVIDER=groq
EMBEDDING_PROVIDER=ollama
EMBEDDING_MODEL=bge-m3
OLLAMA_BASE_URL=http://host.docker.internal:11434
GROQ_API_KEY=
TAVILY_API_KEY=            # 웹 검색 사용 시
```

### 4.2 운영 환경
```env
DB_HOST=prod-db
LLM_PROVIDER=openai
EMBEDDING_PROVIDER=openai
EMBEDDING_MODEL=text-embedding-3-small
OPENAI_API_KEY=${SECURE_KEY}
TAVILY_API_KEY=${SECURE_TAVILY_KEY}   # 웹 검색 사용 시
JWT_SECRET=${SECURE_JWT_SECRET}
```

> 배포 환경은 임베딩 모델이 개발 환경과 다르므로, 배포 후 문서를 **다시 적재(인덱싱)** 합니다. 개발 환경의 Vector DB 파일을 이미지나 볼륨에 포함하지 않습니다.

### 4.3 비밀정보 관리
- `.env` 는 `.gitignore` 에 등록, 저장소에는 `.env.example` (값 없는 샘플)만 커밋
- CI/CD 에서 사용하는 값은 GitHub Secrets 에 등록 (강사 제공 OpenAI Key 포함)
- Kubernetes 사용 시: 민감하지 않은 설정은 ConfigMap, 민감 정보는 Secret

## 5. 클라우드 배포

### 5.1 AWS EC2 (필수)
- VPC / 보안그룹: 인바운드 허용 포트 목록과 사유
- EC2 에 Docker, Docker Compose 설치 및 배포 절차
```bash
# 배포 스크립트
docker compose pull && docker compose up -d
```

### 5.2 Kubernetes (선택 · 가산점)
> 적용한 경우에만 작성합니다. 아래 중 사용한 환경을 표시하세요.
> - [ ] Minikube (로컬)
> - [ ] GCP GKE (클라우드) – 클러스터 이름/리전, 노드 수·머신 타입, 이미지 레지스트리(Docker Hub 또는 Artifact Registry), 외부 접속 주소를 기재
```yaml
# Kubernetes 매니페스트 (Deployment / Service / ConfigMap / Secret)
apiVersion: apps/v1
kind: Deployment
```
- 서비스 노출 방식: ClusterIP / NodePort / LoadBalancer 중 선택 근거 (GKE는 LoadBalancer 외부 IP)
- (GKE) 비용 관리: 시연 후 클러스터 삭제 여부
- 설정 분리: ConfigMap vs Secret 구분 내역

## 6. CI/CD

```yaml
# GitHub Actions
name: Deploy
on:
  push:
    branches: [main]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Build & Push Docker Image
      - name: (선택) Deploy to EC2
```

- Backend / Frontend / AI Module 별 워크플로우 구성
- 사용한 Secrets 목록 (값은 기재 금지): `DOCKERHUB_TOKEN`, `EC2_SSH_KEY` 등
