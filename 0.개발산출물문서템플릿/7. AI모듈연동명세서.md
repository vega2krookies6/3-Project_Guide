# AI 모듈 연동 명세서

## 1. 기술 스택

- **AI Framework**: LangChain
- **API 서버**: FastAPI (REST API, SSE 스트리밍)
- **언어**: Python 3.12
- **패키지·가상환경 관리**: uv 0.12.23
- **Vector DB**: FAISS 또는 Chroma
- **LLM**: 개발·테스트 Groq / 배포 OpenAI (사용 모델명 명시)
- **임베딩**: 개발·테스트 Ollama bge-m3 / 배포 OpenAI text-embedding-3-small
- **웹 검색**: Tavily (`langchain-tavily`, 필요한 경우)
- **관측**: LangSmith (선택)

## 2. 프로젝트 구조

```
ai-module/
├── src/
│   ├── api/           # FastAPI 서버
│   ├── chains/        # LangChain 체인
│   ├── tools/         # Tool 정의 (RAG 검색, Tavily 웹 검색)
│   ├── core/          # 핵심 로직
│   └── utils/         # 유틸리티
├── pyproject.toml     # 의존성 정의 (uv add 로 관리)
├── uv.lock            # 의존성 버전 고정 (Git 커밋 필수)
├── .python-version    # Python 버전 (3.12)
├── .dockerignore      # .venv, .env 제외
└── Dockerfile
```

> `.venv/` 와 `.env` 는 Git 에 커밋하지 않습니다.

### 2.1 개발 환경 실행
```bash
uv sync                                   # 의존성 설치 (.venv 생성)
uv add <패키지명>                          # 의존성 추가 (pyproject.toml, uv.lock 갱신)
uv run uvicorn src.api.main:app --reload --port 8000
```

## 3. 환경 설정

### 3.1 환경별 모델
| 구분 | 개발·테스트 (로컬) | 배포 (EC2 / K8s) |
|------|--------------------|-------------------|
| LLM | **Groq** (무료) | **OpenAI** (유료) |
| 임베딩 | **Ollama bge-m3** (무료, 로컬, 1024차원) | **OpenAI `text-embedding-3-small`** (1536차원) |
| API Key | `GROQ_API_KEY` | `OPENAI_API_KEY` |

### 3.2 환경변수
```env
# 공통
LLM_PROVIDER=          # groq | openai
LLM_MODEL=
EMBEDDING_PROVIDER=    # ollama | openai
EMBEDDING_MODEL=       # bge-m3 | text-embedding-3-small
VECTOR_STORE_PATH=     # 임베딩 모델별로 경로 분리

# 개발·테스트
GROQ_API_KEY=
OLLAMA_BASE_URL=

# 배포
OPENAI_API_KEY=

# 선택
TAVILY_API_KEY=        # 웹 검색 사용 시 (개발·배포 공통)
LANGSMITH_API_KEY=
```

### 3.3 모델 전환 방식
- 모델·공급자는 코드에 직접 쓰지 않고 환경변수로 선택합니다. (선택 로직이 있는 파일과 함수명 기재)
- 임베딩 모델이 바뀌면 벡터 차원이 달라지므로, 배포 환경에서는 문서를 다시 적재(인덱싱)합니다. 개발 환경의 인덱스 파일을 복사하지 않습니다.

## 4. 주요 API

> LangServe는 사용하지 않습니다. **FastAPI 라우터로 REST API를 직접 구현**합니다.
> 이 API는 Backend만 호출하는 내부 API이며, 외부에 공개하지 않습니다.

| 메서드 | URL | 설명 | 응답 형식 |
|--------|-----|------|-----------|
| POST | `/chat` | 질의응답 (전체 응답) | `application/json` |
| POST | `/chat/stream` | 질의응답 (스트리밍) | `text/event-stream` (SSE) |
| POST | `/documents` | 문서 업로드 및 적재(인덱싱) | `application/json` |
| GET | `/health` | 헬스체크 | `application/json` |
| POST | `/{경로}` | {업무별 AI API} | |

### 4.1 질의응답
- Request (Pydantic 모델로 검증)
```json
{ "question": "", "userId": "" }
```
- Response – `/chat`
```json
{ "answer": "", "sources": [] }
```
- Response – `/chat/stream` (FastAPI `StreamingResponse` + LangChain `astream()`)
```
data: {"token": ""}
data: [DONE]
```

### 4.2 오류 처리
- 입력값 검증 실패: `422` (FastAPI 기본) 또는 `400`
- LLM 호출 실패·타임아웃: `502` / `504`, 오류 상세는 서버 로그에만 기록

## 5. RAG 시스템

### 5.1 문서 처리
1. 파일 로드
2. 텍스트 분할
3. 임베딩 생성
4. 벡터 저장

### 5.2 질의응답
1. 질문 임베딩
2. 유사 문서 검색
3. 컨텍스트 생성
4. LLM 응답 생성

### 5.3 웹 검색 결합 – Tavily Tool (필요한 경우)
> 업로드 문서만으로 답할 수 없는 최신·외부 정보가 필요할 때 사용합니다. 사용하지 않으면 "해당 없음"으로 기재합니다.

| 항목 | 내용 |
|------|------|
| 사용 목적 | {어떤 질문에서 웹 검색이 필요한지} |
| 구현 방식 | `TavilySearch` Tool + `create_agent` / LangGraph / 수동 Tool-Calling 중 선택 |
| 등록 Tool 목록 | 예: `retrieve_documents`(RAG), `web_search`(Tavily) |
| 검색 설정 | `max_results` = , 검색 도메인 제한 여부 |
| Tool 선택 규칙 | 예: 내부 문서 우선 → 결과가 없을 때만 웹 검색 (시스템 프롬프트에 명시) |
| 출처 표시 | 답변에 검색 URL 포함 여부 |

처리 흐름
1. 사용자 질문 수신
2. LLM이 필요한 Tool 판단 (Reason)
3. RAG 검색 또는 Tavily 웹 검색 실행 (Act)
4. Tool 결과(ToolMessage)를 바탕으로 최종 답변 생성 (Observe → 답변)

## 9. AI 보안

> 점검·조치 결과는 `9. 보안점검서.md` 4장에 기록합니다. (OWASP LLM Applications Top 10 참고)

- **Prompt Injection 대응**: 시스템 프롬프트 분리, 사용자 입력 길이 제한, 출력 검증
- **데이터 격리**: 사용자별 문서/벡터 컬렉션 분리 (타 사용자 문서 검색 방지)
- **비용·자원 보호**: 요청 크기/횟수 제한, 타임아웃
- **키 관리**: LLM·Tavily API Key는 환경변수로만 주입, 로그 출력 금지
- **웹 검색 결과 검증** (Tavily 사용 시): 검색 결과는 외부 입력으로 취급 (간접 Prompt Injection 주의), 답변에 출처 표시
