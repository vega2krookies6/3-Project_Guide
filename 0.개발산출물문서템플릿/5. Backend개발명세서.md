# Backend 개발 명세서

## 1. 기술 스택

- **Framework**: Spring Boot 4.0.x (Spring Security 7.x)
- **언어**: Java 17
- **데이터베이스**: MariaDB
- **빌드**: Maven

## 2. 프로젝트 구조

```
backend/
├── src/main/java/com/{팀명}/{프로젝트명}/
│   ├── controller/     # REST API
│   ├── service/        # 비즈니스 로직
│   ├── repository/     # 데이터 액세스
│   ├── entity/         # JPA 엔티티
│   ├── dto/            # 데이터 전송 객체
│   └── config/         # 설정
├── src/main/resources/
│   └── application.yml
└── pom.xml
```

## 3. 주요 설정

```yaml
# application.yml
server:
  port: 8080

spring:
  datasource:
    url: 
    username: 
    password: 
  jpa:
    hibernate:
      ddl-auto: validate   # 스키마 변경은 Flyway 마이그레이션으로 관리

jwt:
  secret: ${JWT_SECRET}               # 코드/설정 파일에 값을 직접 쓰지 않는다
  access-expiration: 900000           # Access Token (짧게)
  refresh-expiration: 1209600000      # Refresh Token (DB 저장)

management:
  endpoints:
    web:
      exposure:
        include: ${ACTUATOR_EXPOSURE:health,info}
```

## 5. 보안 구현

> 점검·조치 결과는 `9. 보안점검서.md` 에 기록합니다. 여기서는 **구현 방식**을 기술합니다.

### 5.1 인증/인가
- Spring Security FilterChain 구성
- JWT: Access/Refresh 분리, Refresh Token 해시 저장·폐기·재발급
- 접근 제어: `@PreAuthorize` + 리소스 소유자 검증 (IDOR 방지)

### 5.2 공격 방어
| 위협 | 방어 방식 | 구현 위치 |
|------|-----------|-----------|
| SQL Injection | JPA 파라미터 바인딩 | Repository |
| Brute Force | 로그인 실패 횟수 제한 / 계정 잠금 | |
| CSRF | (적용 또는 비활성 사유 기재) | SecurityConfig |
| XSS | 응답 헤더 CSP 등 | SecurityConfig |
| 입력값 검증 | DTO `@Valid` | dto/ |

### 5.3 설정·로그
- CORS: 허용 Origin 한정
- Actuator: 필요한 엔드포인트만 노출, `/actuator/**` ADMIN 제한
- 감사 로그: 로그인 성공/실패, 401/403 (민감정보 마스킹)
- 예외 처리: 500 스택 트레이스는 서버 로그에만, 사용자 응답에 노출 금지
